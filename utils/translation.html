Sì. L'errore nello screenshot è abbastanza chiaro: non è un errore di DBeaver in sé, ma di BigQuery (DBeaver sta semplicemente mostrando l'errore restituito dal database).

Il messaggio principale è:

No matching signature for operator IN for argument types DATE and {TIMESTAMP}

Cosa significa

Nella query hai probabilmente una condizione simile a:

WHERE data_rif IN (
    TIMESTAMP '2026-09-01 00:00:00',
    TIMESTAMP '2026-08-01 00:00:00'
)

ma data_rif è di tipo DATE, mentre i valori dentro IN sono di tipo TIMESTAMP.

BigQuery non fa automaticamente questa conversione nel confronto con IN.

Per esempio:

DATE_colonna IN (TIMESTAMP_valore)

❌ genera esattamente questo errore.

Come correggerlo

Se la colonna è DATE, devi utilizzare valori DATE:

WHERE data_rif IN (
    DATE '2026-09-01',
    DATE '2026-08-01'
)

oppure, se i valori che hai a disposizione sono timestamp:

WHERE data_rif IN (
    DATE(timestamp_colonna1),
    DATE(timestamp_colonna2)
)
Attenzione al caso più probabile nel tuo scenario

Visto che stai lavorando con BigQuery e avete modificato la colonna di partizione da:

mese_rif STRING   -- yyyy-MM

a:

data_rif DATE     -- yyyy-MM-01

è molto probabile che la query o il filtro di DBeaver stia passando delle date come TIMESTAMP.

Ad esempio, se hai:

WHERE data_rif IN (
    '2026-09-01 00:00:00',
    '2026-08-01 00:00:00'
)

BigQuery può interpretare quei valori come TIMESTAMP, causando il problema.

Puoi forzare esplicitamente il tipo:

WHERE data_rif IN (
    DATE('2026-09-01'),
    DATE('2026-08-01')
)

oppure:

WHERE data_rif IN (
    CAST('2026-09-01' AS DATE),
    CAST('2026-08-01' AS DATE)
)
